## Requirements
Re-planned 24 Nov for Level 2 (a general engine plus templates; see ARCHITECTURE.md). Slices 1–6c were built on the fixed attendance model and stay `done` as history. The L slices move that work onto the general engine.

- **R1 (must):** Accept a plain-language policy, purpose and environment (max 2,000 characters each), pre-filled with our 80% example, so that `policy example` prints the stored policy with an `id` and the 80% text.
- **R2 (must):** Turn the policy into a blueprint (template + values) in two Bedrock calls: pick the template or say it's out of scope, then fill that template's values. Every value is labelled as a user fact or an AI assumption, checked against the template, and frozen on approval. Check: `blueprint create` prints:
  - for the example: `template: attendance@1`, `threshold_pct 80`, a request-timing rule and `status: valid`;
  - for the curfew example: `template: hostel_curfew@1`;
  - for an off-topic policy: `status: out_of_scope`.

  A run on an unapproved blueprint is refused.
- **R3 (must):** Run a general engine over a template, with permissions and preconditions from the template and blueprint, not code. Check: `engine check --case tests/cases/student_c.json --core` prints today's four attendance lines, and `engine check --case tests/cases/curfew_r2.json --core` prints a curfew count against its ladder.
- **R4 (must):** LLM people decide only when a trigger affects them. They're prompted from the template and their blueprint profile, and return a validated decision that records its trigger. Rule roles come from the fixed library. A per-run call cap, a 40 s phase deadline, and "no action" on every Bedrock error. Check: test runs on both templates record decisions only for triggered people, and none past the cap.
- **R5 (must):** Run the blueprint's disruptions (obstacle, capacity, cancellation) at their phase. Check: a fixed-input test on each template follows `caused_by` from a check result back to the disruption.
- **R5b (must, slice 6c, ported in L8):** Stress variants change only the template's `environment` parameters, and `explore run` reports `broke` per variant.
- **R6 (must):** Run simulations in a background thread, one at a time, with pollable progress. Check: `POST /api/runs` returns a `run_id` at once (409 if one is running), and `GET /api/runs/{id}` moves to `completed`, `degraded` or `failed`.
- **R7 (must):** Detect, on any template, **check failed** (objective failure) and **request still pending at the check** (bottleneck), each with the ordered chain found by following `caused_by` links.
- **R8 (must):** `GET /api/findings/{id}/evidence` returns the ordered steps, each with `event_id`, state change, calculation and a label, in the template's own terms.
- **R9 (must):** Open any stored run by ID and restore the seeded demo run (a recorded real run on the new format, bundled with its policy and blueprint) with one command.
- **R10 (must):** Serve the app live on AWS (EC2 + Bedrock via the instance role, SQLite on EBS, CloudFront HTTPS, Budgets alert, daily caps, status-check alarm). Check: the full curl flow works through the `cloudfront.net` URL, and a run over the daily cap gets HTTP 429.
- **R11 (nice):** Counterfactual: change one environment parameter, keep everything else matched, and compare.
- **R12 (nice):** CloudWatch logs and custom metrics (LLM calls, tokens, run duration).
- **R13 (nice):** Three-policy comparison: vary only `policy` parameters under matched conditions.
- **R21 (nice, Brief rank 11, planned 25 Nov as slice 16):** Guided scenario search: rounds of AI-targeted and random scenarios, each round told how close the last runs came to failing, stopping at a break confirmed by a rerun.
- **R14–R27 (nice):** Brief ranks 4–17. Not planned in this build, except R21 (slice 16); AI-drafted templates (Level 3) are not planned either.

**Proof conventions:**
- Run from the repo root with the virtual environment active.
- Run proofs in **Git Bash**. In PowerShell, `curl` is a different command: use `curl.exe` and put the body in a file, `-d "@body.json"`.
- `python -m pytest …` runs with `RULESTORM_ENV=test` and the fake model (set in `tests/conftest.py`).
- Every `cli` command without `pytest` uses real Bedrock and needs your profile in `AWS_PROFILE` (`aws login --profile rulestorm-dev`).
- `curl` proofs need `python -m uvicorn rulestorm.api:app --port 8000` running.
- Test-only numbers (like Student C's 15/20) live in test files, never in app code or templates.
- Blueprints saved before L6a won't load on the new format. Create new ones with `blueprint create`.
- The old engine is the fallback at git tag `pre-level2` (commit `189ac53`).
- **General-feature rule (24 Nov):** a building block or engine feature is added only if a second template could use it. Template-specific words, labels and sentences live in the template's terms and parameter sentences, never in `core/` or `prompts.py`. Tests prove behaviour and numbers exactly; they don't require copying one template's old wording, because that pushes the engine to grow features only one template needs.
